[07.11.2026] Найденные дефекты проекта и правки в развёрнутой копии
  ВАЖНО: исходный репозиторий D:\nlbbootstrap-main не изменялся.
  Все правки сделаны только в D:\bitrix doker\www.
  1. db/run.php: nlb_iblock_id() кеширует 0 (db/lib/helpers.php:34), поэтому
     после шага 002 шаг 003 не видит инфоблоки. Обход: миграции по одной.
     В репозитории функцию надо чинить (не кешировать нулевой ID).
  2. CEventType::GetList() с фильтром по EVENT_NAME/LID возвращает все строки,
     из-за чего 008/012 не создавали типы событий. Типы созданы прямым SQL.
  3. local/php_interface/init.php: nlb_db.php использует CIBlock, но модуль
     iblock не подключён -> 500 «Class "CIBlock" not found» на всех страницах.
     Добавлено: \Bitrix\Main\Loader::includeModule('iblock').
  4. Шаблон breadcrumb вызывал $this->setFrameMode(), а включается из
     CMain::GetNavChain ($this = CMain) -> 500. Обёрнуто в method_exists().
  5. Формы заявок передавали 'GROUPS' => [] — компонент iblock.element.add.form
     пускает только админов, гость не мог отправить форму (ошибок нет, форма
     просто не обрабатывалась). Исправлено на [2] в feedback/index.php,
     services/detail.php, books/detail.php.
  6. Поля формы назывались PROPERTY[NAME], а компонент ждёт PROPERTY[NAME][0]
     -> в NAME попадал только первый символ (или пусто). Исправлено в
     local/php_interface/include/nlb_forms.php (и чтение $_POST).
  7. У инфоблоков requests/bookings/orders миграция 002 ставит CODE и XML_ID
     обязательными, а форма их не передаёт -> «Обязательное поле "Символьный
     код" не заполнено». В БД стенда снят IS_REQUIRED для CODE/XML_ID
     (b_iblock_fields, ID 7/8/9), плюс OnBeforeIBlockElementAdd генерирует
     CODE/XML_ID для элементов форм.
  8. В nlb_forms.php вызывалась nlb_site_id(), а она определена только в
     db/lib/helpers.php (в рантайме сайта её нет) -> Error ловился catch
     и письма молча не создавались. Добавлена guarded-функция nlb_site_id()
     в nlb_forms.php.
  9. urlrewrite.php: условия вида '#^/services/([a-z0-9_-]+)/#' без якоря
     ломались на query string: /services/<code>/?sent=1 уходил в 404
     (правило склеивало CODE с параметрами). Условия detail-правил заменены
     на '#^/<раздел>/([a-z0-9_-]+)/?(?:\?(.*))?$#i' с 'RULE' => 'CODE=$1&$2'.
     Проверено: detail + ?sent=1 = 200, списки (?section=, ?PAGEN_1=) = 200.
